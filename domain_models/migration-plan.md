# CLI migration plan

## Status

Approved for implementation. A single native cutover is in progress, including native Mise tasks; completion and publication remain gated by the validation criteria below. `webp` 0.3.1 with resolved `libwebp-sys` 0.9.6 is selected conditionally: all four platform encoder build/smoke checks and the resolved dependency license audit must pass before publishing. Only macOS ARM64 has been validated locally so far; no cross-platform or release completion is claimed.

## Goal and scope

Move remaining CLI responsibilities into a native Rust executable invoked through a small Node launcher, preserving agreed public behavior. Keep a constrained Node adapter for executable TypeScript config evaluation/validation and existing Vite/tsup builds. Keep npm as the install channel via platform-specific optional binary packages. Make one coordinated cutover and remove WASM-only interfaces from the final runtime/build.

Do not add workflow-plugin build support (workflow is represented in config but currently has no build implementation). Do not replace Comrak/html5ever with regex or custom scanning. Do not silently replace/restrict Vite, tsup, or executable config capability.

## Accepted decisions

1. **Meaning of “in Rust”:** compiled Rust executable is the actual `caido-dev` command and owns CLI parsing/help/version/exit status, orchestration, package filesystem operations, package assembly, ZIP generation, and watch lifecycle.
2. **Node boundary:** a small Node launcher selects/invokes the native binary from platform-specific optional npm packages. Node is required for every CLI invocation, including help/version. Build/watch also use a constrained Node adapter because `caido.config.ts` is executable and current builds invoke Vite and tsup. The adapter evaluates config/imports, validates with existing Zod, and executes the existing build ecosystem.
3. **Adapter interface:** one-shot versioned JSON over stdio; stdout protocol-only, stderr diagnostics, child exit/failure propagated. Arbitrary Vite JS/function values remain in the adapter. Rust receives validated serializable packaging config and build output metadata, not file bytes. Every version 1 response has `{ version: 1, config, buildOutputs, assetMatches }`, where `assetMatches` maps each distinct asset pattern from built frontend/backend outputs to an array of absolute matched source path strings. Load returns `buildOutputs: []` and `assetMatches: {}`; build expands only after all plugins finish, using exactly `new Glob(pattern, { cwd })` and retaining directory matches. Node does no asset filesystem validation, content reads, recursive collection, copying, or packaging; Rust validates all paths and owns those operations.
4. **Public API:** retain npm package export `defineConfig` unchanged. It remains a typed identity helper; validation occurs when CLI loads config.
5. **Filesystem and packaging:** Node retains asset glob pattern expansion only, using glob 11.0.1 defaults; Rust owns matched-path validation, recursive directory collection, asset reads, package source checks, leaf/parent symlink/containment checks, README reads, package layout/collision checks, manifest, ZIP and output replacement. Preserve output checks before reads and immediately before replacing `dist/`; document containment is not race-proof.
6. **README:** retain Comrak AST and html5ever tokenizer/serializer, transformation rules, URL behavior, formats and constraints. Preserve 1600×1600 maximum without enlargement, GIF animation preservation for qualifying GIFs and first-frame behavior otherwise, 64 MiB source cap, 40 MP cap, 100 KiB encoded image cap, 2 MiB final README cap, quality retry policy 80→20 by 10 with method 6/lossless disabled intent. Encoded WebP bytes may differ from `@jsquash/webp`.
7. **Native WebP dependency:** `webp` 0.3.1 with resolved `libwebp-sys` 0.9.6 is selected conditionally. Encoder build/encoding smoke checks on Linux x64/ARM64, Windows x64, and macOS ARM64, plus a license audit of the resolved graph, gate publishing. Only macOS ARM64 has been validated locally so far. If checks fail or build requirements are unacceptable, stop and reopen the dependency decision; do not silently produce lossless output. `image-webp` and the built-in `image` encoder are lossless-only; `webp::Encoder` exposes quality, method, and lossless configuration. Documentation target listings do not establish build support.
8. **Distribution:** npm stays installation channel with target-specific optional packages. The npm package uses a small Node command shim to select the platform-specific optional binary. Node is therefore required for every invocation; actual CLI behavior remains in Rust. Initial targets: Linux x64, Linux ARM64, Windows x64, macOS ARM64. No initial promise for macOS x64 or Windows ARM64.
9. **Exit statuses:** 0 for successful commands/help/version; 2 for CLI argument/usage failures, including no subcommand; 1 for config/build/runtime failures. This intentionally changes malformed arguments from current status 1 to 2.
10. **Watch:** retain HTTP GET `/plugin_package.zip`, configured port, `connected` (`packageId`, `downloadUrl`), `rebuild` (`downloadUrl`), and `error` (`error`) JSON fields. Coalesce rapid events with a 200 ms trailing-edge debounce, serialize builds (one active plus at most one trailing rebuild for events received during the active build), reload valid config and watch roots, retain last valid setup on invalid config, preserve last good package on failures, handle disconnected clients safely, and gracefully close watcher/WebSocket/HTTP/build resources on SIGINT/SIGTERM. Port changes require restarting watch; other config/root changes reload live. Initial build failure keeps the watcher/server available and serves 404 until the first package; invalid initial config watches the config path (and root package metadata) for recovery. Port bind failure exits with status 1, reports the port and OS reason, cleans up resources, and does not select a fallback port.
11. **Migration:** single cutover, not a staged dual-published path. Workflow build remains out of scope.

## Migration phases (single cutover implementation sequence)

1. **Pre-cutover feasibility gates:** verify the launcher selects the correct optional package on all targets; review `webp`/`libwebp-sys` license and native build requirements; compile and perform encoder smoke tests on four targets. If the encoder gate fails, return for a dependency decision rather than implementing an unapproved alternative.
2. **Native Rust architecture:** separate reusable platform-neutral Rust modules from WASM code; add executable entrypoint; implement clap CLI/error/status handling and adapter process supervision; remove JS/WASM APIs from final code.
3. **Node adapter:** implement versioned one-shot JSON contract; load config via existing jiti/Zod; preserve arbitrary Vite options and imports; run sequential Vite/tsup operations with working-directory/module resolution intact; stderr diagnostics/stdout protocol separation.
4. **Native packaging:** Rust validates adapter glob matches, recursively collects matched directories, and performs safe asset reads, README processing with Comrak/html5ever and native encoder, package/manifest/ZIP construction, preflight checks and safe `dist` replacement. Use temporary/atomic replacement where feasible without changing specified layout.
5. **Native watch:** implement HTTP download route, WebSocket protocol and watcher in Rust; coalescing/serialization, config reload/root refresh, last-valid config, last-good output, disconnect safety and graceful shutdown; port reload limitation as agreed.
6. **CLI/npm/CI cutover:** establish optional platform binary packages and the small Node launcher; build/publish/test four target binaries; update main npm package and coordinated publish workflow. Keep Node dependency/runtime wording accurate and adapter dependencies present where build/watch needs them.
7. **Tests and parity:** retain/port meaningful Rust package/README tests; add adapter protocol and CLI golden tests; run existing frontend/backend playgrounds against native `caido-dev`; compare old/new extracted package contents; verify native targets.
8. **Docs/tooling cleanup:** update README, AGENTS.md (including stale architecture instructions), Mise tasks, CI/publishing workflows, metadata and lockfiles; remove obsolete WASM build/docs/interfaces and generated artifacts; perform the single cutover only after all acceptance checks pass.

## Measurable completion criteria / validation strategy

- **CLI:** automated golden matrix asserts 0 for help/version/success, 2 for malformed/unknown args/missing required command, and 1 for config/build/runtime failures; verifies command/options and sensible diagnostics.
- **Adapter:** protocol tests cover version mismatch, malformed request/response, stdout contamination, stderr diagnostics, child nonzero exit, signal, missing Node, config imports/custom config path, invalid Zod config, and preserved Vite plugin/function configuration.
- **Playgrounds:** both existing frontend and backend playground suites pass through the native command; exact manifest assertions, JS/CSS entry content, asset inclusion/exclusion and README URL rewriting continue to pass. Workflow remains unbuilt.
- **Rust tests:** package destination safety, case-insensitive duplicates, file/directory collisions, manifest semantics, archive entry safety, README parser behavior via Comrak/html5ever, supported schemes/HTML contexts/reference links, GIF preserve/first-frame rules, image format/URI mismatch, 64 MiB inclusive and growth detection, 40 MP, 100 KiB, 2 MiB, WebP quality/size retry, no enlargement, path traversal/absolute/percent-encoded paths, symlink and output-sentinel protections.
- **Watch/protocol:** integration tests assert `/plugin_package.zip` success/404, configured/default port, exact connected/rebuild/error JSON fields, bursts coalesce, no overlapping builds, config reload and root refresh, invalid reload retains last valid config, failed build leaves last package intact, disconnects are safe, port-change notice, and graceful SIGINT/SIGTERM cleanup.
- **Package parity:** compare extracted old/new path sets, exact manifest semantics, README transformations and plugin output bytes where deterministic. ZIP compressed bytes and WebP payload bytes are explicitly not required to match; every rewritten image must decode as supported WebP, fit the cap, and pass representative visual/size checks.
- **Platform/install:** on Linux x64/ARM64, Windows x64, macOS ARM64, install package arrangement, prove launcher selects and runs the right binary; help/version work through the launcher; verify build/watch adapter behavior and smoke-test WebP encoder. Unsupported targets produce actionable diagnostics.
- **Repository checks:** `mise run build:prod`, `mise run typecheck:prod`, `mise run test`, `mise run format:prod`, `mise run lint:prod`, `mise run knip:prod`, `mise --env dev run audit:prod`, and `mise --env dev run zizmor`; ensure CI/publish workflows and all generated output/package contents are checked.

## Risks and constraints

- **npm launcher:** the accepted revision allows a small Node launcher to select the optional native binary. It must handle omitted/missing optional packages, unknown platforms, Windows executable naming, and report actionable errors.
- **Build adapter:** arbitrary config imports, working directory, package resolution, Vite plugin hooks, user stderr/stdout, and Node engine compatibility may be fragile across process boundaries.
- **Node version declaration:** current engines are Node `>=20`; retain that bound wherever Node remains and verify chosen adapter tools support declared engines. The launcher requires Node for every invocation, including help/version; do not restore the superseded no-Node launch requirement.
- **WebP:** native libwebp target/build/license support is not established by docs for three targets. No silent lossless fallback; if targets/dependency gate fails, stop and reconvene.
- **Security/output safety:** filesystem containment and symlink checks need equivalent Rust coverage; do not claim they eliminate TOCTOU races. Config/build hooks remain user-controlled code. Preflight/config/build failures must leave existing `dist/` intact; use temp output plus atomic swap where supported, and test/document any platform-specific limit on rollback after low-level write failures.
- **Watch:** queue semantics and graceful process shutdown are behavior changes; ensure old package remains available if any build or config reload fails.
- **Publishing:** coordinated versioning and failure recovery for optional packages; publish only when every accepted target is ready.
- **Single cutover:** all major surfaces change together; acceptance gates and old/new fixture comparison are mandatory.

## Release infrastructure scope

The native npm cutover requires a runtime launcher, a portable native build helper, one release-staging entrypoint, and an internal third-party notice collector. Release staging creates the universal package and the matching platform package together; package metadata uses one source version. It does not need separate main/native command-line tools, a separate test runner, runtime downloads, or a release framework.

Launcher, manifest, notice, and installed-package checks belong in the existing Vitest suite. Installed-package checks run against locally packed archives on each release target; source/playground tests alone cannot catch lost executable permissions or missing installed adapter dependencies. The release job publishes the exact tested archives. Cargo source fetching belongs in the shared test task, not duplicated matrix steps.

Production implementation and test size must be reported separately. Extracting inline Rust tests improves review boundaries but does not reduce total code; simplification means removing redundant argument parsing, forwarding functions, and duplicate validation—not deleting coverage or weakening recovery/output guarantees.

## Remaining implementation specifications

These do not change accepted architecture and should be finalized as concrete test values in implementation:

- Exact adapter operations and JSON schema/version negotiation details.
- Concrete tests for the already agreed initial watch failure/recovery and port-bind failure contract in accepted decision 10 (not an open behavior decision).
- Native package replacement implementation on each OS (atomic swap where feasible, preserving sentinel safety).
- Exact visual/image comparison procedure for WebP without asserting byte identity.
